1 Introduction

1.1 Project Title and Overview

TexEye AI: AI-Based Fabric Defect Detection and Quality Management System is an automated fabric inspection and quality management system developed to replace error-prone manual inspection with modern computer vision, hardware integration, a mobile floor application, and a centralized web management dashboard.

During production, a camera captures continuous fabric images while a rotary encoder precisely measures fabric movement to calculate the exact physical locations of defects. The AI model detects fabric flaws and tracks them across consecutive frames, preventing duplicate records of the same defect.

A central feature of TexEye AI is its proactive inspection reliability monitoring. The system continuously verifies camera connectivity, lighting conditions, image clarity, and frame capture rates. When any condition falls below reliable thresholds, the system alerts operators and marks those fabric sections as uninspected. During network outages, all defect data, images, and roll records are buffered locally on the edge unit and synchronized automatically once connectivity is restored.

1.2 Problem Statement

Manual fabric inspection during high-speed production frequently misses defects due to human fatigue and visual strain, leading to severe fabric waste, customer returns, and financial losses. Furthermore, manual inspection lacks precise defect location tracking, real-time alerting, and reliable digital records.

In existing setups, unforeseen camera disconnections, poor lighting, dropped frames, or blurred optical conditions can cause sections of fabric to pass completely uninspected without the operator being aware. TexEye AI solves these critical challenges by detecting and locating defects in real time, actively monitoring inspection reliability, clearly recording uninspected sections, and providing complete digital review, grading, and quality reporting.

1.3 System Capabilities and Objectives

  • Automated Defect Detection: Identify surface defects (holes, stains, thread flaws) using computer vision.
  • Metric Location Tracking: Estimate physical defect positions (X in mm, Y in meters) using rotary encoder pulses.
  • Multi-Frame Deduplication: Track moving defects across consecutive frames to avoid redundant flaw counting.
  • Reliability Sentinel: Monitor camera connectivity, lux levels, and image quality; flag uninspected sections on failure.
  • Offline Resilience: Securely buffer inspection sessions locally on the stand during network disconnects.
  • Mobile Operator App: Enable workers to receive floor alerts, scan roll QR codes, and review detected flaws.
  • Web Quality Management: Display 2D defect maps, roll grading records, inventory summaries, and PDF reports.
  • Secure Access Control: Enforce authentication and role-based authorization across web and mobile interfaces.

2 Overall Description

2.1 Name and Detail of System Modules

TexEye AI is partitioned into five specialized, cohesive modules that coordinate between the physical inspection stand, edge processing, mobile floor clients, and web management systems:

  • 1. AI Defect Detection and Location Module: Detects fabric defects using computer vision, estimates their physical locations along the roll using rotary encoder measurements, and tracks defects across consecutive frames to eliminate duplicate records.
  • 2. Hardware and Inspection Monitoring Module: Integrates the camera, LED lighting, rotary encoder, and audio-visual alert mechanisms. Continuously monitors camera connectivity, lighting conditions, image sharpness, and dropped frames, identifying and marking fabric sections that were not successfully inspected.
  • 3. Mobile Floor Application: Equips shop-floor workers with tools to receive instant defect and inspection alerts, scan roll QR codes, view roll specifications, and review or manually correct detected flaws directly at the machine stand.
  • 4. Web Quality Management and Digital Fabric Map: Displays full roll defect maps, inspection statuses, quality grading, and inventory records. Supports automated digital inspection report generation and handles local storage synchronization when internet connectivity returns.
  • 5. Smart Operations Module: Maintains long-term quality records, roll inventory data, scrap logs, and defect occurrence statistics to support production auditing, decision making, and compliance reporting.

UC-03: Real-Time Defect Detection & Kalman Tracking
Use Case ID / NameUC-03: Real-Time Defect Detection & Kalman Tracking
Primary ActorHardware Stand (Autonomous Edge Engine; Secondary: Floor Operator)
PreconditionsInspection session is active; fabric is moving across the optical inspection zone.
PostconditionsConfirmed defects saved to SQLite with metric coordinates (X, Y), physical dimensions, and JPEG crop.

2. Edge engine submits frame to fine-tuned YOLO defect detection engine.
3. YOLO detects candidate anomaly bounding boxes [u_min, v_min, u_max, v_max] with confidence ≥ 0.40.
4. 2D Kalman Filter predicts active track positions and associates detections via Hungarian IoU matching.
5. When a candidate matches an active track, its trajectory and physical length L (mm) are updated.
6. Once a track achieves ≥ 3 consecutive frame hits, it is elevated to CONFIRMED_DEFECT status.
7. When flaw exits the FOV, edge engine calculates finalized coordinates: lateral X (mm) and longitudinal Y (m).
8. Edge engine extracts high-resolution JPEG crop and writes defect record to local SQLite within 30 ms.
Alternative Flows 6a. Anomaly detected in fewer than 3 frames: Track discarded as surface dust or loose lint.
7a. Continuous flaw (long warp streak): System updates ongoing record, incrementing length without duplicating flaw.

4.3 Software Quality Attributes

4.3.1 Reliability & Invariant Preservation

Reliability is founded on the Non-Negotiable Inspection Invariant: A fabric roll shall never be certified as defect-free if any segment traversed the inspection zone during an unmonitored or optically degraded state.

  • Atomic State Transitions: Inspection sessions transition through formal deterministic states (INITIALIZING to RUNNING to PAUSED to UNINSPECTED to COMPLETED). No corrupt intermediate state is permissible.
  • Dual-Storage Fault Tolerance: Every defect event is committed to local SQLite WAL storage prior to network transmission, ensuring zero data loss during plant-wide blackouts or Wi-Fi drops.
  • Autonomous Hardware Reconnection: If camera USB resets or encoder drops connection, edge daemon re-enumerates hardware within 500 ms without manual restarts.

4.3.2 Correctness and Verifiability

  • Deterministic ASTM Grading: The ASTM D5430 penalty calculator implements a purely deterministic mathematical formulation verified against published international standards. Given identical flaw inputs, grading output is 100% reproducible.
  • Metrological Precision: Lateral pixel-to-millimeter calibration factors (kx) are verified using physical calibration grid targets, achieving spatial coordinate accuracy within plus/minus 2 mm.
  • Deduplication Accuracy: The Kalman-IoU tracker eliminates double-counting of traversing defects with ≥ 98% tracking continuity on continuous streaks up to 10 meters in length.

4.3.3 Reproducibility & Traceability

  • Traceable Lineage: Every committed defect record stores raw bounding box pixels, normalized physical coordinates, AI model version hash, camera frame timestamp, and encoder pulse index.
  • Deterministic Replay: Archived raw frame video sequences can be replayed through the AI engine to evaluate updated model weights against historical ground-truth runs.
  • Audit Compliance: All changes to defect classifications made by human inspectors require an explicit rationale entry, maintaining complete traceability for export compliance audits.

4.3.4 Maintainability and Design for Change

  • Decoupled Modular Architecture: The hardware ingestion layer, AI inference engine, local storage outbox, and cloud sync daemon operate as decoupled services. Upgrading YOLO from v8 to v11 requires replacing only the TensorRT engine file without altering ingestion or UI code.
  • Externalized Configuration: Physical parameters (roller circumference, encoder PPR, lighting lux limits, camera resolution) are defined in an external YAML configuration file, enabling rapid stand recalibration without code recompilation.

4.3.5 Testability

  • Hardware-in-the-Loop (HIL) Simulation: The edge engine includes a virtual camera and simulated encoder pulse generator capable of streaming synthetic fabric video and quadrature pulses for automated regression testing.
  • Automated Test Coverage: Core algorithms (ASTM penalty capping, coordinate transformation, Kalman tracking, outbox state machine) maintain ≥ 85% automated test coverage using PyTest.

4.3.6 Usability, Portability & Interoperability

  • High-Contrast Shop-Floor UI: Mobile and stand screens utilize high-contrast themes (≥ 7:1 ratio) with oversized touch targets (≥ 48x48 px), enabling seamless operation by workers wearing gloves.
  • Color-Blind Accessible Overlay: Defect overlays utilize distinct geometric glyphs (squares, diamonds, triangles, circles) in addition to color hues for color-blind operators.
  • Cross-Platform Edge Deployment: Edge software stack is containerized using Docker, verified on NVIDIA Jetson Linux (aarch64) and standard industrial x86_64 PCs.
  • Standard Data Exchange: All external API payloads, database exports, and cutting-room integration files adhere strictly to standard JSON and CSV formats.

5.6.2 System Algorithms

This section details the primary algorithms governing metric coordinate tracking, safety gating, and automated ASTM D5430 4-point penalty accumulation.

Algorithm 5.1: Encoder Quadrature Metric Coordinate Tracker 
Input:  Delta_P (quadrature pulse delta), PPR = 1024 (pulses/rev), D_roller = 100 mm (diameter)
Output: Y_current (absolute longitudinal meters along roll)
1: Resolution_mm_per_pulse = (pi * D_roller) / (4 * PPR)
2: Distance_delta_mm = Delta_P * Resolution_mm_per_pulse
3: Y_current = Y_previous + (Distance_delta_mm / 1000.0)
4: Return Y_current
Algorithm 5.2: Real-Time Lighting & Motion Blur Invariant Guard 
Input:  Frame I (grayscale image), v_fabric (current fabric speed in m/s)
Output: Status in {RELIABLE, FAULT_LIGHTING, FAULT_BLUR, FAULT_OVERSPEED}
1: Mean_Illuminance_Lux = ComputeMeanPixelIntensity(I) * LuxCalibrationFactor
2: If Mean_Illuminance_Lux < 800:
3:     Return FAULT_LIGHTING
4: Blur_Score = VarianceOfLaplacian(I)
5: If Blur_Score < 100.0:
6:     Return FAULT_BLUR
7: If v_fabric > 0.50:
8:     Return FAULT_OVERSPEED
9: Return RELIABLE
Algorithm 5.3: Multi-Frame Kalman Defect Associator 
Input:  ActiveTracks T, Detections D = {b_1, b_2, ... b_k}, IoU_Threshold = 0.45
Output: UpdatedTracks T_updated, NewDefectRecords R_new
1: For each track t in T: Predict Kalman state [x, y, vx, vy] forward by dt
2: CostMatrix = Compute_IoU_Distance_Matrix(T, D)
3: Matches, UnmatchedDetections, UnmatchedTracks = LinearAssignment(CostMatrix, IoU_Threshold)
4: For each (t, d) in Matches: UpdateKalman(t, d.bbox)
5: For each d in UnmatchedDetections: CreateNewTrack(d)
6: For each t in UnmatchedTracks: If t.missed_frames > 3: FinalizeAndSaveDefect(t); Remove(t)
7: Return T_updated, R_new
Algorithm 5.4: ASTM D5430 4-Point Penalty Accumulator 
Input:  DefectList D, RollLength_Meters L, FabricWidth_Meters W
Output: TotalPoints, PointsPer100SqMeters, FinalGrade in {Grade A, Grade B, Reject}
1: Partition roll length into 1-meter linear bins: Bins = [0 to 1m, 1 to 2m, ..., L-1 to Lm]
2: For each defect d in D:
3:     L_mm = d.physical_length_mm
4:     If L_mm <= 75.0: Points = 1
5:     Else if L_mm <= 150.0: Points = 2
6:     Else if L_mm <= 230.0: Points = 3
7:     Else: Points = 4
8:     If d.type == HOLE: Points = (d.diameter_mm <= 25.0) ? 2 : 4
9:     Bin_Index = Floor(d.coord_y_m)
10:    Bins[Bin_Index].accumulate_points(Points)
11: For each bin b in Bins: b.points = Min(b.points, 4) // ASTM cap: max 4 points per linear meter
12: TotalPoints = Sum(b.points for b in Bins)
13: Area_SqM = L * W
14: PointsPer100SqM = (TotalPoints * 100.0) / Area_SqM
15: If PointsPer100SqM <= 20.0 and MaxConsecutiveFaults < 3: FinalGrade = "Grade A"
16: Else if PointsPer100SqM <= 40.0: FinalGrade = "Grade B"
17: Else: FinalGrade = "Reject"
18: Return TotalPoints, PointsPer100SqM, FinalGrade
